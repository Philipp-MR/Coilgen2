# CoilGen2 review: GUI and mathematics (3 November 2026)

This review examined the native workbench from a user's perspective (a screenshot tour of every model node and of a completed Halbach Gz run) and the numerical mathematics from target definition to fabricated conductor. Every finding marked **verified** was reproduced with a script against real runs or analytical references; the scripts are in the session scratchpad (`math_review_sheet/`, `math_review_winding/`, `ux_review/`, `tour/`). Hypotheses are labelled as such. No engine behaviour was changed by this review.

## 1. Summary

The numerical core is sound where it matters most. The following were verified:

- The basis functions, the Biot–Savart prefactor and the resistance matrix are correct. P = xᵀRx is in watts, and a MATLAB area²/R+Rᵀ bug has been fixed.
- The gauge and hole handling is correct.
- The mesh converges: power for the cylinder converges to 10.95 W, and efficiency is stable at 1.077 mT/m/A.
- The current per turn follows exactly from Δψ, and contour extraction is robust.

What users see on top of that core is not yet trustworthy:

1. **The same design is reported with three error figures and two drive currents.** The GUI headline is the most pessimistic of them, and nothing tells the user which current to drive.
2. **The error budget is spent on a pure gain error.** Around 45 % of a 3 % budget goes to shrinking the amplitude, which a slightly higher current would undo.
3. **Several reported failures are artefacts or self-inflicted.** One "wire crossing" is a numerical false positive. The templates' own lift and cut-width settings cannot satisfy their own clearance and bend checks.
4. **Expression targets are silently zero for any component other than Bz.** This affects every horizontal-B0 (Halbach) user.
5. **Inductance is biased low by 6–18 %.**

All of these are fixable, and most fixes are small.

### Correction to an earlier statement

The Halbach templates first routed Gz along the bore axis, because Gz "crossed wires" along B0. That crossing was artefact C3. The axis choice is not better in general, and for Gx the bore axis creates a real connector collision. The templates now route all three gradients along B0, and `interconnection_axis` remains a per-design option. The colleague reply draft and `docs/PARAMETERS.md` have been corrected.

## 3. GUI from a user's perspective

### Top improvements (ranked)

1. **Results that answer the engineer's question** (C1). The first row shows efficiency (mT/m/A), the drive current for the requested gradient, the gradient at the design current, and the shape (linearity) error in the DSV, each with its limit and a pass/fail chip. The second row shows R, L, wire length, power at the drive current and τ = L/R. Add a toggle for errors "as wound" vs "scaled to target", and a "remove best-fit gain" option in residual views.
2. **Docked inspector with inline fields.** Settings currently open as a floating, non-dockable 520×791 px window over the 3D view (`workbench.py` ~1031-1040). Each card opens yet another window, and there are four ways to commit an edit. Change to:
   - a docked inspector that follows the tree selection (keyboard included);
   - collapsible sections with inline fields and validation as you type;
   - a single *Apply* button.
3. **Human labels and consistent units.** `_combo` shows stored enum text (`constrained_quadratic`, `linear_fit`, `mr_gradient`, `centroid`, …). Other inconsistencies:
   - axes in metres with ticks like 0.0827/−0.0828;
   - residual colour bars in tesla (±2.07e-05 T);
   - both "uT" and "µT";
   - ROI "20 mm" shown without saying it is a radius.

   Fix with one label/unit registry shared by Qt and the browser, a units preference (mm, µT, mT/m), and rounded mm ticks.
4. **Magnet and frame as a first-class step.** The desktop has no editor for `b_0_direction` and no B∥B0 plot component. Add a first card: magnet type (solenoid, bore ∥ B0 / Halbach, bore ⊥ B0), B0 ±x/±y/±z buttons with the live arrow, and the bore axis. Derive the routing direction from these instead of exposing an enum.
5. **"Checks failed" becomes a fix list.** Show a table of Observed / Required / Margin / Where (click to fly there in 3D) / Suggested change with a *Try* button. Give three verdicts: *Field OK*, *Windable*, *Printable*. Map DRAFT failure codes through the existing readable titles in `application/diagnostics.py`.
6. **One consistent state model.** A loaded run currently shows "Not computed" / "0/5 steps" next to "Available" results, an "Earlier model" badge at the same revision, and "Another channel" in a single-channel project. Replace these with one banner that states the run's origin, the number of differing settings, and Compare / Adopt / Recompute actions.
7. **3D view that carries the engineering.**
   - Zoom field views to the DSV automatically.
   - Add three orthogonal linearity slices with ±1/2/5 % contours.
   - Show a colour bar in µT or %.
   - Show current direction arrows and start/end terminals.
   - Make the results panel collapsible.
   - Add standard ±X/±Y/±Z views and a measure tool.
8. **Printable former and print bundle (hackathon-critical).**
   - Former: support shell with grooves (wire profile plus print tolerance) via manifold boolean, plus flanges.
   - Printing aids: bed-size splitting with pins, and embossed axis/start/end labels.
   - Output: a watertight check, and a bundle with STL in mm, path CSV, wire length plus slack, R, L, drive current and a wiring diagram.
9. **First run and fewer concepts.**
   - Start page with template cards and recent projects.
   - Basic/Expert mode that hides *Gradient engineering* and *Research studies*.
   - Status icons instead of the text column that truncates tree labels ("Geometry and …").
   - Help → user guide, shortcuts and a tour.
   - Autosave and crash recovery.
10. **Browser to hackathon quality.**
    - HTML colour bar and legend, and a semi-transparent support.
    - Layout that adapts to screen size.
    - Unit dropdown with bounding-box auto-detection on STL import.
    - Automatic download after export.
    - Shared result tiles and labels with the desktop.
    - Team page with queue and ETA.

## 5. Routing: root cause and proposed algorithm

The cut plane normal is b0 × n̄ for one global axis (layout.py ~3173-3198). The axis has to serve within-group rails and inter-group connectors at the same time, and it is undefined where it projects to zero (n̄ ∥ axis). This explains the Halbach results:

- **Gz:** the main groups are indifferent to the axis; the side groups differ.
- **Gx along the bore:** two connector legs share one axial corridor at the same 2 mm lift and collide.

**Proposal:**

1. Develop each group onto its tangent plane, or unroll the cylinder.
2. Enumerate 12–24 rail directions per group, plus the directions towards neighbouring groups and the boundary.
3. Keep only rails that cross each loop once.
4. Score each rail by:
   - minimum turn gap against the S-bend requirement √(4Rs−s²) ≤ w;
   - rail length;
   - exit position relative to connector targets;
   - the exact Biot–Savart perturbation of the defect loops.
5. Choose per-group directions and the group order jointly (the search space is tiny).
6. Route connectors as straightened shortest paths.
7. Assign lift levels by colouring the crossing graph, so no two overlapping bridges share a level.
