# GUI and example-layout review

This report records the first GUI review. The [updated winding gallery](../gui_winding_quality_2026-11-03/README.md) compares these saved designs with the finer support meshes and guarded local fits now offered by the templates.

The desktop and browser show what to do after computation and let the user inspect the **submitted revision** after editing the model. Newly loaded gallery examples request surface contour smoothing. Previously saved designs keep their recorded settings.

## What smoothing does

For the gradient and shim examples, **smoothing acts on closed contours before routing**. Each fit is traced back onto the support mesh. An original contour is retained if a proposed fit would violate the displacement, topology or spacing guard. Subsequent connections, return paths, sweep frames, conductor offsets and physical clearances still need their own checks.

Across the 19 templates (29 channel instances, 42 supports), **482 of 1,051 loops** accepted a fit. Another 358 exceeded the displacement limit, 24 failed the surface-topology check, and 187 retained the extracted contour for spacing. The largest accepted displacement was **0.499718 mm**. Stream functions, sheet fields, independent sheet samples and original currents matched their unsmoothed comparisons. Every channel kept the same contour levels, multiplicities, orientations and closed paths. All 29 sheet checks passed. All 29 pipeline sweeps and strict fabrication reviews failed. None has construction release.

Using the same 3 mm arclength sampling before and after smoothing, the 95th-percentile turn angle improved by more than 0.01° for 24 channels, changed by at most 0.01° for four, and increased for Conical Z2. This statistic describes the contours before routing. At fixed current, the largest worsening in fabricated-winding RMS error was also Conical Z2 (20.739% → 21.130%). The largest improvement was the biplanar system X²−Y² shim (13.729% → 13.244%). The field comparison uses the design DSV. Only the sheet was separately checked on the independent samples.

The [browser result for cylindrical Gy](browser-connected-gradient.jpg) illustrates the distinction. The computation completed and its continuous sheet passed, but the pipeline sweep and strict fabrication checks both failed. The strict review reported a 1.151 mm minimum bend radius against 6 mm required, along with clearance and profile failures. That is a checked design failure, not a crashed job. The gallery marks it accordingly.

## Scope

The hidden internal browser was used for real frontend interactions. The native walkthrough used programmatic Qt actions and real workers. After the request to keep the screen free, all desktop testing used offscreen Qt without desktop mouse or keyboard input. The historical file/CAD handoff exercised the native workbench's non-rendering fallback because the Windows offscreen platform did not provide a native OpenGL surface. The browser rendered the winding itself. Expert dialog and control coverage does not mean every possible physical parameter combination, third-party application or fabrication process was validated.

The broad native run covered 107 test modules: 1,942 tests passed and two identified issues. After the fixes, all 136 tests in the affected files passed. A separate final persistence and export run passed 63 checks using a local, unsynced temporary directory; this included preservation of an existing target, atomic rollback, export progress, and portable file loading. See the [native inventory](native-ui-review.json) for the exact coverage. Platform-native file pickers and GPU rendering on a physical desktop were not exercised offscreen.

On this Windows system, using the actively synced Dropbox checkout as pytest scratch intermittently denied replacement of a test result or deletion of the test's source folder. Both operations passed in local scratch. Use a local workspace for live jobs and share the verified compact project after saving; retries cannot make a file that is still locked writable.
